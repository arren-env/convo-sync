**Why it happened**
- Under T3 Code, Antigravity runs as a different program, `agy_acp_server.exe`, not the `agy` CLI. I unpacked that binary to check what it does. It does load hooks from `$GEMINI_HOME/config/hooks.json`, so the hook files your last commit added in the T3 profile are in the right place.
- Its hook sends `transcriptPath` pointing at `.../antigravity-acp/conversations/<id>.db`, which is a SQLite database. The `agy` CLI sends `brain/<id>/.system_generated/logs/transcript.jsonl` instead.
- Because that `.db` file exists, the adapter never fell back to looking for the transcript by conversation id. It read the database as if it were a transcript, found 0 messages and returned without writing anything. So no `.agents` folder was created. Nothing was logged either, because only errors get logged unless `CONVO_SYNC_DEBUG` is set.

**The fix** is in [antigravity.mjs](scripts/lib/adapters/antigravity.mjs). When `transcriptPath` ends in `.db`, the adapter now uses `<app_data>/brain/<id>/.system_generated/logs/transcript.jsonl` instead, which sits next to it. The `.meta` lookup for the project folder then works too, as a backup when `workspacePaths` is missing. I added a test for this in [antigravity.test.mjs](test/antigravity.test.mjs).
