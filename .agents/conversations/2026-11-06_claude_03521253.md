**Cause:** OpenCode 2.x changed how plugins load. It now only accepts a default export shaped like `{ id, setup }` or `{ id, effect }`. Our plugin used the 1.x style, a named `ConvoSync` export, so 2.x rejected it. 2.x also changed two other things the plugin relies on:
- **Events:** they come from `ctx.event.subscribe()`. The plugin now listens for `session.execution.succeeded`, `.failed` and `.interrupted`.
- **Messages:** they come from `ctx.session.context({ sessionID })` in a new format (`{ type: 'user', text }`, or `{ type: 'assistant', content: [...] }`).

I took all of this from the published `@opencode/plugin@2.2.5` and `@opencode/client@2.2.5` types and from the loader code inside the binary, not from memory.

**Changes:**
- [scripts/opencode-plugin.js](scripts/opencode-plugin.js) adds the 2.x default export and keeps the 1.x `ConvoSync` export. The code that writes the payload file and starts the sync process is now shared by both.
- [scripts/lib/adapters/opencode.mjs](scripts/lib/adapters/opencode.mjs) now reads the 2.x message format as well as the 1.x one. It skips synthetic, system, idle and other non-chat entries.
- I added three tests: one for the 2.x message parser, one for the 2.x export shape, and one that runs the plugin end to end against a fake 2.x event stream.
- **On your machine:** I copied both files into `~/.agents/skills/convo-sync` and reinstalled the OpenCode plugin. Your old plugin file is backed up at `C:\Users\sit390\AppData\Local\Temp\claude\01e0ba609181d2e5\03521253-f716-472f-9655-fdddc9f44ef7\scratchpad\convo-sync.plugin.bak.js`.

**Risks:**
- **1.x compatibility is untested.** The file now has a default export (an object) alongside the old `ConvoSync`. If the 1.x loader tries to call every export as a function, OpenCode 1.x users would see an error. If that happens, the fix is to have the installer check the OpenCode version and write only the matching export.
- **Notes after compaction may be incomplete.** Judging by its name, `session.context` probably returns only what the model currently sees, so after compaction a note might cover only the recent part of the session. I haven't confirmed this.
- **Notes for subagents:** subagent (child) sessions also finish turns, so each may get its own note. That matches what the 1.x plugin did.
- **Docs and commit:** the README still lists `session.idle` as the OpenCode trigger, and none of this is committed yet.
